# 系統邊界與防呆測試報告 (Edge Case Testing)

為確保 Endfield Block Game 核心演算法（Solver）與陣列存取的穩定性，我們設計了以下 7 組極端測資進行壓力測試。所有測資皆已通過驗證，無崩潰或無窮迴圈現象。

## 1. 空間與座標映射測試

* **非對稱座標與障礙物測試 (example1.txt)**
  * **設定**：`5x6` 棋盤，包含 2 個 Blocked cells。
  * **目的**：驗證底層 `M x N` 座標系統映射精確度，確保 `(X, Y)` 軸存取未錯置，並測試零件旋轉放置時的障礙物碰撞偵測是否能防止穿模。
* **極限翻轉與越界測試 (example6.txt)**
  * **設定**：極端細長的 `1x10` 棋盤，搭配 `10x1` 垂直長條零件。
  * **目的**：針對二維陣列邊界檢查（Bounds Checking）的終極測試。驗證垂直零件旋轉置入水平棋盤時，動態長寬互換是否完美對應，嚴防陣列讀取越界。

## 2. 遊戲邏輯與多色結算

* **雙色獨立結算與不干涉測試 (example2.txt)**
  * **設定**：`3x3` 棋盤，兩種顏色賦予不重疊的目標數。
  * **目的**：測試解析器對多顏色區塊的處理。驗證 `rowNeed` 與 `colNeed` 結算系統能各自獨立計算，且嚴格禁止不同顏色零件發生非法重疊。

## 3. Solver 演算法與防呆機制

* **邏輯死胡同測試 (example3.txt)**
  * **設定**：要求填滿 `9` 格，但僅給予 `1` 個 `1x1` 零件。
  * **目的**：測試 Solver 防呆。給予數學上絕對無解的條件，驗證窮舉過程能否果斷判定無解並跳出，防止陷入無窮迴圈導致前端卡死。
* **零需求悖論與提早剪枝測試 (example5.txt)**
  * **設定**：目標需求皆為 `0`，卻強制配發 `1x1` 零件。
  * **目的**：檢驗 Solver 的演算法優化（提早剪枝 Pruning）。確認 Solver 能在嘗試放置第一步時，瞬間察覺數量超出目標並立刻中斷分支搜尋。
* **組合爆炸壓力測試 (example7.txt)**
  * **設定**：`4x4` 棋盤，每行每列需 `1` 格，配發 `4` 個獨立 `1x1` 零件。
  * **目的**：類「八皇后問題」變體。產生極大量排列組合分支，專門對 Solver 的回溯演算法（Backtracking）進行效能極限測試。

## 4. 記憶體極限施壓

* **幽靈零件防呆測試 (example4.txt)**
  * **設定**：`2x2` 零件，但陣列內容全為 `0`（無實體區塊）。
  * **目的**：驗證系統在讀取無實體區塊時，中心點抓取邏輯與矩陣旋轉功能是否具備例外處理能力，避免引發指標越界（Segmentation Fault）。
